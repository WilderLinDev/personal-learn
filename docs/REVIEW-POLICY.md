# Review Policy

## Purpose
Review strengthens long-term retention. It is not a measure of intelligence or personal worth. The goal is to recall and apply knowledge without looking at the note.

## Default intervals
For a newly understood note, start with reviews after:
1. 1 day
2. 7 days
3. 30 days
4. 90 days

These are starting intervals, not rigid rules. Adjust them according to difficulty, importance, and demonstrated recall.

## Outcomes
- Strong recall: accurate explanation and application; move to the next interval.
- Partial recall: core idea present but details missing; review sooner.
- Weak recall: cannot explain without substantial help; return to Learning and shorten the interval.
- Misconception found: correct the canonical note if needed, record the misconception in learning history, and review again after clarification.

## Mastery
- New: not yet studied.
- Learning: introduced or inconsistent recall.
- Understood: accurate unaided explanation of the core idea.
- Mastered: accurate explanation plus transfer to a new example or application.

## Queue
Keep reviews/QUEUE.md synchronized with note-level mastery_status, last_reviewed, and next_review. At a related session, select a small useful set of due items. Do not interrupt unrelated learning with a long backlog.

## No background scheduler
The repository does not run a scheduler. Review dates are surfaced when an AI session reads the queue or when a future website adds a review interface.
