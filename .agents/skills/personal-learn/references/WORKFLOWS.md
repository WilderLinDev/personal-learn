# Personal Learn Workflows

| Session type | Main action | Persistence |
|---|---|---|
| New learning | Teach a new concept or topic | Lesson, learning record, relevant knowledge |
| Continuation | Resume from prior records | Save only meaningful progress |
| Review | Test existing knowledge | Update mastery and review dates; record material misconceptions |
| Connection | Relate existing concepts | Update relations, topic synthesis, and index |
| Correction | Correct an earlier explanation | Revise canonical note and record the correction |
| Application | Solve a real problem | Record the application and transferable lesson |

A user saying they are finished, want to stop, or want to pause is a save boundary. Save as completed or in-progress. Do not wait until the entire topic is mastered.

Before creating a numbered lesson or learning record, inspect the directory and use the next unused four-digit number. Never guess the next number based only on chat history.

Prefer one coherent commit per saved session. If a tool only supports per-file commits, use clear messages and verify each write. Do not report a single atomic commit if multiple commits were actually created.

A one-off factual exchange outside a substantive Teach session does not need a full lesson package.
